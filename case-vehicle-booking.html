project overview

An internal booking tool built during the DepEd ICT internship. Requests are submitted in the browser, reviewed by an administrator, and kept in one organized record.

The system organizes vehicle drop-off and pick-up requests in one web app. A requester submits the trip details, the request receives a control number, and an administrator reviews it in a dashboard.

Booking data is kept in Google Drive and Google Sheets. The dashboard shows request totals by status and a searchable list of requests, and each request opens into a detail view.

The build was part of the DepEd ICT Unit internship in Antipolo. It was made for internal administrative use.

problem statement

Vehicle requests were handled as separate messages and manual notes. The office needed one booking record, a clear approval state, and a notification that did not depend on someone re-typing the details.

objectives

  1. Accept drop-off and pick-up requests in one form.
  2. Give each request a control number and a record.
  3. Let administrators review and update request status.
  4. Send an email notification when a booking is made.
  5. Keep booking data in Google Drive and Google Sheets.

my role and contributions

requirements
Worked with end users to map the booking request, the approval states, and the information the office needed to capture.
build
Implemented the booking form, control numbers, admin dashboard, and email notification flow with Google Apps Script and a browser interface.

Tested the request-to-approval flow and the email notification by hand before review.
refinement
Adjusted the form fields, status labels, and dashboard filters based on user feedback.

AI-assisted development tools were used for parts of the implementation. I reviewed the generated code, tested the flow, and refined the result rather than treating the output as finished.

main features

  2. Control numberGives each request a reference number and a printable record.
  3. Admin reviewAdministrators sign in, open a request, and move it through pending, approved, declined, or rescheduled.
  4. Request dashboardShows request totals by status and a searchable list of bookings.
  5. Request detailKeeps the requester, trip, vehicle, and admin notes together.
  6. Email notificationSends the booking details to the people who need them.
